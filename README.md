# newcutestock — ระบบสต๊อกและขายหน้าร้าน ร้านเสื้อผ้า

- เว็บที่ใช้งานจริง: **https://newcutestock.vercel.app**
- โค้ด: GitHub `newcuteshop/newcutestock` (push ขึ้น `main` แล้ว Vercel deploy ให้อัตโนมัติ)

ระบบนี้ใช้จัดการร้านเสื้อผ้าขนาดเล็กผ่านมือถือเป็นหลัก (รองลงมาคือ iPad):
เก็บรายการสินค้าแยกไซซ์/สี, รับเข้า-จ่ายออก-ปรับยอดสต๊อก, ขายหน้าร้านด้วยการสแกนบาร์โค้ด,
พิมพ์สติกเกอร์บาร์โค้ด, ดูรายงานยอดขาย และกำหนดสิทธิ์พนักงานแต่ละคนได้

## ฟีเจอร์

- **เข้าสู่ระบบ** ด้วยชื่อผู้ใช้ + รหัสผ่าน (ไม่มีสมัครเอง — แอดมินเป็นคนสร้างบัญชีให้)
- **ภาพรวม** ยอดขายวันนี้/เดือนนี้ มูลค่าสต๊อก และสินค้าใกล้หมด
- **สินค้า** แสดงเป็นการ์ด 1 ใบต่อ 1 แบบ (มือถือ 2 คอลัมน์ ถึงจอคอม 6 คอลัมน์) ค้นหาด้วยชื่อ / SKU / บาร์โค้ด
  - **แบบสินค้า** (เช่น "เสื้อยืดคอกลม สีขาว") ติ๊กได้ว่า **มีไซส์หรือไม่มีไซส์**
    - ไม่มีไซส์ = SKU บาร์โค้ด ราคา ชุดเดียว
    - มีไซส์ = 1 ไซส์ต่อ 1 SKU แต่ละไซส์มีบาร์โค้ด ราคาทุน/ขาย จำนวนขั้นต่ำ และสต๊อกของตัวเอง
      (หน้าขาย สต๊อก สติกเกอร์ รายงาน ใช้ทีละ SKU เหมือนเดิม) — คนละสี = คนละแบบ (คนละการ์ด)
  - เอาไซส์ออก: ยังมีสต๊อก = เอาออกไม่ได้ (ปรับยอดเป็น 0 ก่อน หรือปิดขายเฉพาะไซส์นั้น),
    เคยขาย/เคยรับ-จ่าย = เก็บไว้ใน "ไซส์ที่เลิกใช้" (ประวัติอยู่ครบ นำกลับมาใช้ได้), ไม่มีประวัติ = ลบทิ้ง
  - **รูปสินค้าไม่จำกัดจำนวน** ต่อแบบ (ถ่ายจากกล้องมือถือได้) ย่อรูปในเครื่องก่อนอัปโหลด เลื่อนดูได้ในหน้าแก้ไข
    ตั้งรูปปก/เรียงลำดับ/ลบได้ — ไฟล์เก็บใน Supabase Storage ถัง `product-images`
  - **แถบหมวดหมู่** กรองสินค้า และเพิ่ม / เปลี่ยนชื่อ / ลบหมวดหมู่ได้จากหน้ารายการสินค้า
    (ลบหมวดหมู่แล้วสินค้าไม่หาย — ย้ายไปอยู่ "ไม่มีหมวดหมู่")
  - เปิดหน้าแก้ไขค้างไว้ 2 เครื่องแล้วบันทึกทับกันไม่ได้ (เครื่องที่ข้อมูลเก่าต้องกด "โหลดข้อมูลล่าสุด" ก่อน)
    และกดเพิ่มสินค้าซ้ำตอนเน็ตหลุดจะไม่เกิดสินค้าซ้ำ
  - สินค้าที่เคยขายแล้วหรือยังมีสต๊อกเหลือ ลบไม่ได้ ให้กด "ปิดใช้งาน" แทน
- **รับ-จ่ายสต๊อก** รับเข้า / จ่ายออก / ปรับยอด (ใส่ยอดที่นับได้จริง) / รับคืน พร้อมประวัติทุกรายการ
  - ประวัติแสดงจำนวนที่เปลี่ยนเป็น +/− ทุกประเภท, สต๊อกติดลบไม่ได้
- **บันทึกการขาย (POS)**
  - สแกนบาร์โค้ดด้วยกล้องมือถือ หรือเครื่องสแกน USB/Bluetooth
  - ส่วนลดท้ายบิล, ช่องทางชำระ เงินสด / โอนเงิน / บัตรเครดิต
  - **ช่องทางขาย**: หน้าร้าน / Facebook / Instagram / แชต LINE / แชตอื่นๆ
    หลังชำระแต่ละบิล ช่องทางจะกลับเป็นหน้าร้านเอง
  - ราคาคิดจากราคาขายในระบบเสมอ, ตัดสต๊อกพร้อมกันและขายเกินของที่มีไม่ได้
  - กดบันทึกซ้ำหรือเน็ตหลุดกลางทาง จะไม่เกิดบิลซ้ำ
- **พิมพ์บาร์โค้ด** สร้าง PDF สติกเกอร์บาร์โค้ดบนกระดาษ A4 (3 ขนาด)
- **รายงาน** กราฟยอดขาย และสัดส่วนช่องทางชำระ (รวม "ชำระผ่านแพลตฟอร์ม")
  บิลจากออเดอร์แพลตฟอร์มที่ยกเลิกก่อนส่งของ ไม่นับในรายงานและภาพรวม
- **ตั้งค่าการเชื่อมต่อ** (แอดมินเท่านั้น) เชื่อมสต๊อกกับ LINE SHOPPING และ Facebook/Instagram
  - Shopee / Lazada / TikTok Shop เตรียมส่วนเชื่อมต่อร้านไว้แล้ว รอ API อนุมัติ
  - นำเข้า/ส่งออก CSV ได้ทุกช่องทาง
  - ดูหัวข้อ "เชื่อมต่อแพลตฟอร์ม"
- **ผู้ใช้และสิทธิ์** แอดมิน/พนักงาน และเปิด-ปิดสิทธิ์รายเมนูได้ทีละคน
- **กันฐานข้อมูลหลับ** Vercel Cron เรียกฐานข้อมูลวันละครั้ง (ดูหัวข้อ Keep-alive)

### สิทธิ์ผู้ใช้

| สิทธิ์ | ชื่อในระบบ | ทำอะไรได้ |
|--------|-----------|-----------|
| `products` | จัดการสินค้า | เพิ่ม/แก้ไข/ปิดใช้งานสินค้า ไซส์ รูปสินค้า และหมวดหมู่ (ใส่ยอดยกมาของ SKU ใหม่ต้องมีสิทธิ์ `stock` ด้วย) |
| `stock` | รับ-จ่ายสต๊อก | รับเข้า จ่ายออก ปรับยอด รับคืน |
| `sales` | บันทึกการขาย | ขายหน้าร้าน |
| `labels` | พิมพ์บาร์โค้ด | พิมพ์สติกเกอร์ |
| `reports` | ดูรายงาน | ดูรายงานยอดขาย |
| `users` | จัดการผู้ใช้ | สร้าง/แก้ไข/ลบผู้ใช้ และตั้งสิทธิ์ |

แอดมิน (`role = 'admin'`) ได้ทุกสิทธิ์เสมอ ผู้ใช้ที่ไม่มีโปรไฟล์ในตาราง `user_profiles` จะ **ไม่มีสิทธิ์ใดๆ** (ปลอดภัยไว้ก่อน)
สิทธิ์ถูกตรวจทั้งในหน้าเว็บและในฐานข้อมูล (RLS + ฟังก์ชัน) จึงข้ามเมนูไปเรียกข้อมูลตรงๆ ไม่ได้

- บัญชีที่ไม่มีสิทธิ์เลยสักอย่าง อ่านข้อมูลร้านไม่ได้ (สินค้า ยอดขาย ประวัติสต๊อก) และเห็นเฉพาะโปรไฟล์ตัวเอง
- ผู้มีสิทธิ์ `users` ที่ไม่ใช่แอดมิน ให้ได้เฉพาะสิทธิ์ที่ตัวเองมี และแก้/ลบ/ตั้งรหัสผ่านได้เฉพาะบัญชีที่สิทธิ์ไม่เกินตัวเอง
  (ตั้ง Admin, ให้สิทธิ์ "จัดการผู้ใช้" และจัดการบัญชีที่มีสิทธิ์นี้ ทำได้เฉพาะแอดมิน)
- ต้องมีแอดมินอย่างน้อย 1 คนเสมอ ฐานข้อมูลไม่ยอมให้ลด/ลบแอดมินคนสุดท้าย

### ชื่อผู้ใช้และรหัสผ่าน

Supabase Auth รับแค่อีเมล และบังคับรหัสผ่านอย่างน้อย 6 ตัว แอปจึงแปลงให้เองก่อนส่ง (โค้ดอยู่ที่ `lib/auth/credentials.ts`)

- **ชื่อผู้ใช้** (a-z, 0-9, จุด, ขีด `-` `_` ยาวไม่เกิน 32 ตัว) → กลายเป็นอีเมล `ชื่อ@newcute.com` ใน Supabase
  เช่น login ด้วย `max` = บัญชี `max@newcute.com` (บัญชีเดิมของร้านจึงใช้ชื่อ `max` ได้ทันที)
  - พิมพ์อีเมลเต็มในช่องชื่อผู้ใช้ก็ยังได้ (บัญชีที่ใช้อีเมลโดเมนอื่นต้อง login ด้วยอีเมลเต็ม)
  - ไม่สนตัวพิมพ์ใหญ่-เล็ก และตัดเว้นวรรคหน้า-หลังให้
- **รหัสผ่าน** ตั้งกี่ตัวก็ได้ (อย่างน้อย 1 ตัว) แอปเติม `newcute:` นำหน้าก่อนส่งให้ Supabase
  เช่น รหัส `max` เก็บใน Supabase เป็น `newcute:max` — เป็นแค่ตัวแปลงรูปแบบ ไม่ใช่ระบบความปลอดภัยเพิ่ม
  - ยาวได้ไม่เกิน 72 ไบต์รวม prefix (อักษรไทย 1 ตัว = 3 ไบต์)
  - **ตั้ง/เปลี่ยนรหัสผ่านจากเมนู "จัดการผู้ใช้" ในแอปเสมอ** ถ้าจำเป็นต้องตั้งตรงใน Supabase Dashboard / SQL
    ต้องใส่ `newcute:` นำหน้าเอง (อยากให้รหัสเป็น `1234` ให้ใส่ `newcute:1234`)
- **รหัสผ่านเดิม** ที่ตั้งก่อนเปลี่ยนมาใช้ชื่อผู้ใช้ (ไม่มี prefix) ยังเข้าได้ตามเดิม —
  ถ้ารหัสแบบใหม่ไม่ผ่าน หน้า login จะลองรหัสแบบเดิมให้อีกครั้ง (เฉพาะรหัสที่ยาว 6 ไบต์ขึ้นไป — อักษรไทย 1 ตัว = 3 ไบต์)
  เปลี่ยนรหัสใหม่จากเมนู "จัดการผู้ใช้" เมื่อไหร่ ก็จะเป็นแบบใหม่ทันที

## ติดตั้งระบบ (ทำตามลำดับ)

### 1. สร้างโปรเจกต์ Supabase

1. ไปที่ [supabase.com](https://supabase.com) → New project → Region เลือก **Southeast Asia (Singapore)**
2. จด **Database password** เก็บไว้ในที่ปลอดภัย

### 2. รัน SQL ตามลำดับ

ไปที่ **SQL Editor** → New query → วางเนื้อหาไฟล์ → กด **Run** ทีละไฟล์ตามลำดับนี้เท่านั้น

1. `supabase-schema.sql` — สร้างตาราง
2. `supabase-indexes.sql` — index ให้ค้นหาเร็ว
3. `supabase-users.sql` — ระบบสิทธิ์ผู้ใช้
4. `supabase-fix-01.sql` — ฟังก์ชันบันทึกขาย/ตัดสต๊อกที่ปลอดภัย (`record_sale`, `move_stock`) และปิดการแก้สต๊อกตรงๆ
5. `supabase-fix-02.sql` — แบบสินค้า (`product_groups`) + ไซส์แยก SKU + รูปสินค้า (`product_images` และถัง Storage
   `product-images`) + กติกาหมวดหมู่ และฟังก์ชันเพิ่ม/แก้/ลบสินค้า (`save_product_group`, `get_product_group`,
   `set_product_group_active`, `delete_product_group`, `add_product_image`, `delete_product_image`, `reorder_product_images`)
   — ต้องรันคู่กับการ deploy โค้ดรุ่นนั้น (ดูกล่องด้านล่าง)
6. `supabase-fix-03-integrations.sql` — ระบบเชื่อมต่อแพลตฟอร์ม และช่องทางขายของบิล
   (`sales.channel`, `sales.voided_at`, วิธีชำระ `marketplace`) — รันก่อนหรือพร้อม deploy รุ่นนี้ (ดูกล่องด้านล่าง)
7. `supabase-cron-integrations.sql` — ตัวปลุกงานอัตโนมัติของระบบเชื่อมต่อ
   ไม่บังคับ แต่ต้องรันถ้าจะให้ส่งสต๊อกหรือดึงออเดอร์เอง
   ดูหัวข้อ "เชื่อมต่อแพลตฟอร์ม" และใส่ค่าลับใน SQL Editor ตอนรัน ห้ามบันทึกลงไฟล์

> **สำคัญ — โปรเจกต์ที่ใช้งานอยู่แล้ว (ตัวจริงของร้าน) ต้องรัน `supabase-fix-01.sql` ด้วย**
> โค้ดรุ่นนี้บันทึกขายและรับ-จ่ายสต๊อกผ่านฟังก์ชันในไฟล์นี้ ถ้ายังไม่รัน จะขายและรับ-จ่ายสต๊อกไม่ได้
> และหลังรันแล้ว โค้ดรุ่นเก่าจะบันทึกขายไม่ได้ จึงควรทำตอนร้านปิด ตามลำดับนี้
>
> 1. สำรองข้อมูลเป็น CSV ก่อน (ดูหัวข้อ "สำรองข้อมูล")
> 2. **Authentication → Sign In / Providers → ปิด Allow new users to sign up** (ต้องทำ — เดิมใครรู้ที่อยู่ Supabase
>    ของร้านก็สมัครบัญชีเองได้ ร้านสร้างบัญชีจากเมนู "จัดการผู้ใช้" อยู่แล้ว)
> 3. รัน `supabase-fix-01.sql` ใน SQL Editor ของโปรเจกต์จริง
> 4. deploy โค้ดรุ่นใหม่ขึ้น Vercel ทันที
> 5. **ตรวจรายชื่อบัญชีที่ SQL Editor แสดงหลังรันข้อ 3** (Admin และผู้มีสิทธิ์จัดการผู้ใช้อยู่บนสุด)
>    เจออีเมลที่ร้านไม่รู้จัก ให้ลบทันทีที่ Authentication → Users — ก่อนแก้ไฟล์นี้ คนนอกสมัครแล้วตั้งตัวเองเป็น Admin ได้
>    แล้วรันคำสั่ง (ค) ท้ายไฟล์ `supabase-fix-01.sql` หาสินค้าที่สต๊อก/ราคาติดลบค้างจากระบบเก่า
>    สต๊อกติดลบ → เมนูรับ-จ่ายสต๊อก → "ปรับยอด" ให้ตรงของจริง, ราคาติดลบ → แก้ในหน้าแก้ไขสินค้า
> 6. ทดลองขาย 1 บิล และรับเข้าสต๊อก 1 รายการ ให้แน่ใจว่าใช้ได้

> **สำคัญ — `supabase-fix-02.sql` ต้องรันพร้อมกับการ deploy โค้ดรุ่นนี้ (หน้าสินค้าแบบการ์ด)**
> หลังรันไฟล์นี้ แอปแก้ตาราง `products` ตรงๆ ไม่ได้อีก ต้องผ่านฟังก์ชันใหม่เท่านั้น จึงต้องเปลี่ยนทั้งคู่พร้อมกัน:
> โค้ดรุ่นเก่า + ฐานข้อมูลใหม่ = เพิ่ม/แก้ไข/ลบ/ปิดใช้งานสินค้าไม่ได้ (ขึ้น "ไม่มีสิทธิ์ทำรายการนี้")
> ส่วนโค้ดรุ่นนี้ + ฐานข้อมูลที่ยังไม่รัน = หน้าสินค้าเปิดไม่ขึ้น (ยังไม่มีตาราง/ฟังก์ชันใหม่)
> หน้าขาย รับ-จ่ายสต๊อก สติกเกอร์ และรายงาน ใช้ได้ตามปกติตลอด ควรทำตอนร้านปิด ตามลำดับนี้
>
> 1. สำรองข้อมูลเป็น CSV ก่อน (ดูหัวข้อ "สำรองข้อมูล")
> 2. ต้องรัน `supabase-fix-01.sql` มาแล้ว (ไฟล์ fix-02 ตรวจให้ ถ้ายังไม่ได้รันจะหยุดโดยไม่แก้อะไร)
> 3. รัน `supabase-fix-02.sql` ใน SQL Editor ของโปรเจกต์จริง (ทั้งไฟล์สำเร็จทั้งหมดหรือไม่เปลี่ยนอะไรเลย · รันซ้ำได้)
> 4. deploy โค้ดรุ่นนี้ขึ้น Vercel **ทันที** แล้วกด Ctrl+Shift+R (หรือปิด-เปิดแอปบนมือถือ) ทุกเครื่อง

## เชื่อมต่อแพลตฟอร์ม (เมนู "ตั้งค่า → ตั้งค่าการเชื่อมต่อ")

เชื่อมสต๊อกของแอปกับร้านบน LINE SHOPPING, Facebook/Instagram, Shopee, Lazada, TikTok Shop และช่องทางอื่น
ร้านไม่ได้ใช้ ZORT หรือโปรแกรมรวมร้านตัวอื่น ทุกช่องทางจึงเชื่อมกับแพลตฟอร์มโดยตรง
**ห้ามเชื่อมโปรแกรมรวมร้านตัวอื่นกับร้านเดียวกันซ้อนอีก** เพราะสต๊อกจะถูกตัดซ้ำ 2 ครั้ง

### ทำอะไรได้ในรอบนี้

| ช่องทาง | สถานะ | ทำอะไรได้ |
|---------|-------|-----------|
| LINE SHOPPING (MyShop Open API) | ใช้งานจริงได้ | ส่งสต๊อกอัตโนมัติ, รับออเดอร์ทาง webhook และดึงออเดอร์ซ้ำกันพลาด แล้วตัด/คืนสต๊อกในแอป |
| Facebook / Instagram (Catalog) | ใช้งานจริงได้ | ส่งสต๊อก ราคา และรูปเข้า Catalog แต่ Facebook/IG ในไทยไม่มีระบบออเดอร์ ขายทางแชตให้บันทึกที่หน้าขายโดยเลือก "ช่องทางขาย" |
| Shopee / Lazada / TikTok Shop | รออนุมัติ API | มีปุ่มเชื่อมต่อร้าน (OAuth) และต่ออายุ token ให้แล้ว ส่วนส่งสต๊อกและรับออเดอร์จะเพิ่มเมื่อได้คีย์จริง ระหว่างรอให้ใช้ CSV |
| ช่องทางอื่น | ใช้ได้ทันที | นำเข้าไฟล์ CSV ออเดอร์เพื่อตัดสต๊อก และส่งออก CSV สต๊อก |

ทุกช่องทาง **นำเข้า CSV ออเดอร์** ได้ (ใช้ตอนระบบเชื่อมต่อล่ม) ถ้าออเดอร์เดียวกันมาทาง CSV และทาง webhook
ไม่ว่าจะมาทางไหนก่อน ระบบจะตัดสต๊อกครั้งเดียว (จับคู่บรรทัดด้วย SKU)

### กติกาสต๊อก (ตามที่บอสตัดสินใจ)

- **แอปนี้เป็นสต๊อกหลัก** สต๊อกบนแพลตฟอร์มถูกเขียนทับด้วยค่าจากแอปเสมอ ห้ามไปแก้จำนวนสต๊อกในหลังร้านของแพลตฟอร์มเอง เพราะรอบถัดไปจะถูกทับ
- **ตัดสต๊อกทันทีที่ออเดอร์ถูกสร้าง** (ยังไม่จ่ายก็ตัด) หรือตั้งเป็น "ตัดเมื่อจ่ายแล้ว" แยกต่อช่องทางได้
- **ยกเลิกก่อนส่งของ** จะคืนสต๊อกอัตโนมัติ และบิลของออเดอร์นั้นขึ้นว่า "ยกเลิก" ไม่นับในภาพรวมและรายงาน
  ส่วน **ยกเลิกหลังส่งของหรือคืนสินค้า** ต้องให้แอดมินกด "รับของคืนแล้ว" ก่อน สต๊อกจึงจะกลับเข้าแอป
- **ขายเกินของที่มี** ระบบไม่ปฏิเสธออเดอร์ จะตัดเท่าที่มี แล้วติดธง "ขายเกิน" สีแดง และส่งสต๊อก 0 ของ SKU นั้นไปทุกช่องทางทันที
- **กันสต๊อกต่อช่องทาง (buffer)** ส่งไปแพลตฟอร์มเป็น max(0, สต๊อก − buffer) ตั้งต่อช่องทางหรือต่อรายการได้
- **จับคู่สินค้าด้วย SKU** แบบตรงทุกตัวอักษร ไม่สนตัวพิมพ์ใหญ่-เล็กและช่องว่างหัวท้าย ถ้าไม่ตรงให้เลือกคู่เองในแท็บ "จับคู่สินค้า"
  ดังนั้น **SKU บนแพลตฟอร์มต้องตรงกับ SKU ในแอป** ทีละไซส์

> **คำเตือน: "ส่งสต๊อกครั้งแรก" จะทับสต๊อกบนแพลตฟอร์มทั้งหมด**
> ทุกช่องทางต้องกดปุ่ม "ส่งสต๊อกครั้งแรก" เองก่อน 1 ครั้ง ก่อนกด ระบบจะไม่ส่งสต๊อกไปเลย
> ก่อนกดให้ตรวจ 3 อย่าง
> 1. นับสต๊อกในแอปให้ตรงของจริง
> 2. ดูตาราง "ก่อน/หลัง" ในหน้านั้น
> 3. ตรวจแท็บ "จับคู่สินค้า" ว่าไม่มีรายการที่ขัดแย้งหรือยังไม่จับคู่
>
> ถ้าตัดการเชื่อมต่อแล้วเชื่อมใหม่ ต้องยืนยันส่งสต๊อกครั้งแรกอีกครั้ง

### ความปลอดภัย

- เมนูนี้ใช้ได้เฉพาะ **แอดมิน** (`role = 'admin'`) ไม่มีสิทธิ์ย่อยให้พนักงาน ฐานข้อมูลตรวจซ้ำอีกชั้น
- คีย์ร้าน, App Secret, token และ webhook secret ถูกเข้ารหัส AES-256-GCM ฝั่งเซิร์ฟเวอร์ด้วย `INTEGRATIONS_ENC_KEY` ก่อนเก็บลงฐานข้อมูล
  - มีแต่เซิร์ฟเวอร์ (service_role) ที่อ่านได้ แม้แต่แอดมินก็อ่านไม่ได้
  - ค่าเหล่านี้ไม่ถูกส่งกลับมาที่หน้าเว็บ หน้าเว็บเห็นแค่ `ตั้งค่าแล้ว •••• 1a2b` และไม่ถูกเขียนลงบันทึกการซิงก์
- webhook ต้องมีลายเซ็นถูกต้องจึงจะรับ และรับเหตุการณ์เดียวกันซ้ำจะไม่ตัดสต๊อกซ้ำ
- `/api/integrations/worker` ต้องมี `Authorization: Bearer <INTEGRATIONS_WORKER_SECRET>`
- แอปเรียกออกได้เฉพาะเซิร์ฟเวอร์ทางการของแพลตฟอร์มเท่านั้น
- ลิงก์ฟีดสินค้าใช้โทเคนสุ่มที่เดาไม่ได้ และเปิดเผยเฉพาะข้อมูลสินค้าสาธารณะ (ไม่มีต้นทุน ไม่มีข้อมูลลูกค้า) กด "สร้างลิงก์ใหม่" เพื่อยกเลิกลิงก์เก่าได้
- **ห้ามทำ `INTEGRATIONS_ENC_KEY` หาย** ถ้าหาย คีย์ที่บันทึกไว้ทั้งหมดจะถอดไม่ได้ ต้องกรอกคีย์ใหม่ทุกช่องทาง ให้เก็บสำรองไว้ในที่ปลอดภัย
  - ถ้าต้องการเปลี่ยนกุญแจ:
    1. ย้ายกุญแจเดิมไปไว้ที่ `INTEGRATIONS_ENC_KEY_PREVIOUS` และเลขรุ่นเดิมไว้ที่ `INTEGRATIONS_ENC_KEY_PREVIOUS_VERSION`
    2. ใส่กุญแจใหม่ที่ `INTEGRATIONS_ENC_KEY` และเพิ่ม `INTEGRATIONS_ENC_KEY_VERSION` ขึ้น 1
    3. Redeploy
    4. กดบันทึกคีย์ของทุกช่องทางใหม่ แล้วจึงลบกุญแจเดิมออก

### ตัวปลุกงานอัตโนมัติ (`supabase-cron-integrations.sql`)

ระบบส่งสต๊อกด้วยคิว ทุกครั้งที่สต๊อกเปลี่ยน ระบบจะเข้าคิวให้เอง คนที่ปลุก worker ให้ทำงานตามคิวมี 3 ทาง

- **pg_cron ในฐานข้อมูล** (ไฟล์นี้) ปลุกทุก 30 วินาทีหรือ 1 นาที เฉพาะตอนมีงานจริง และปลุกงานรายวันอีก 1 ครั้ง (ต่ออายุ token และล้างข้อมูลเก่า)
- webhook ที่เข้ามาจะปลุก worker ช่วงสั้นๆ ให้เอง
- กด **"ซิงก์ตอนนี้"** ในหน้าตั้งค่า

ถ้าไม่รันไฟล์นี้ สต๊อกที่ขายหน้าร้านจะไม่ถูกส่งไป LINE/Facebook จนกว่าจะกด "ซิงก์ตอนนี้"
**ถ้าจะใช้งานจริง ต้องรันไฟล์นี้**

1. สุ่มค่าลับบนเครื่องตัวเอง: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`
2. ใส่ค่าลับที่ Vercel ชื่อ `INTEGRATIONS_WORKER_SECRET` แล้วกด Redeploy
3. เปิด SQL Editor แล้ววางไฟล์ `supabase-cron-integrations.sql`
4. แก้บรรทัด `v_secret text := '...'` เป็นค่าลับเดียวกัน แล้วกด Run
   - **ห้ามบันทึกไฟล์ที่ใส่ค่าลับแล้วลง GitHub** เพราะ repo เป็น public
   - รันซ้ำได้ ถ้าไม่แก้ค่าลับ ระบบจะใช้ค่าเดิมใน Vault
5. ตรวจผลด้วยคำสั่งในหัวไฟล์ (`cron.job_run_details` และ `net._http_response`) ต้องเห็น status 200 จาก Vercel

   - อย่ากด "ดึงรายการจากแพลตฟอร์ม" บ่อยๆ ให้กดเฉพาะตอนเพิ่มหรือแก้สินค้าบน LINE เพราะ LINE ห้ามดึงรายการทั้งหมดซ้ำๆ และอาจบล็อกคีย์

   1. "ทดสอบการเชื่อมต่อ"

   - Meta รับการส่งสต๊อก 1 ชุดต่อ Catalog ต่อ 1 นาที ชุดละไม่เกิน 500 ไซส์

## Keep-alive (กันฐานข้อมูลหลับ)

Supabase แพ็กเกจฟรีจะ **หยุดโปรเจกต์อัตโนมัติถ้าไม่มีการใช้งาน 7 วัน** (ร้านเคยโดนหยุดไป 5 เดือน)
ระบบจึงให้ Vercel Cron เรียก `/api/cron/keepalive` วันละครั้ง เวลา 03:00 UTC (ประมาณ 10:00 น. เวลาไทย
— แพ็กเกจ Hobby อาจคลาดเคลื่อนภายในชั่วโมงนั้น) ซึ่งจะ query ฐานข้อมูลเบาๆ 1 ครั้ง

- ตรวจว่า cron ทำงาน: Vercel → Project → **Settings → Cron Jobs** ต้องเห็น `/api/cron/keepalive`
  กด **Run** เพื่อทดลอง และดู log ได้ (cron ทำงานเฉพาะ Production deployment)
- ทดสอบเอง (ถ้าตั้ง `CRON_SECRET`)

  ```bash
  curl -H "Authorization: Bearer <CRON_SECRET>" https://newcutestock.vercel.app/api/cron/keepalive
  ```

  ต้องได้ `{"ok":true,"at":"..."}` (ถ้าไม่ได้ตั้ง `CRON_SECRET` เปิดลิงก์ในเบราว์เซอร์ได้เลย)
- ถ้าโปรเจกต์ถูกหยุดไปแล้ว: เข้า Supabase Dashboard → เลือกโปรเจกต์ → **Restore project**

## สำรองข้อมูล (ทำเป็นประจำ)

**Supabase แพ็กเกจฟรีไม่มีไฟล์สำรองให้ดาวน์โหลด** ถ้าข้อมูลหายจะกู้คืนไม่ได้ จึงต้อง export เก็บเอง

- อย่างน้อยทุกสัปดาห์ (และทุกครั้งก่อนรัน SQL ใหม่): Supabase → **Table Editor** → เลือกตาราง →
  ปุ่ม **Export** (หรือคลิกขวาที่ชื่อตาราง → Export data) → เลือก **CSV**
- ตารางที่ต้อง export: `product_groups`, `products`, `product_images`, `categories`, `sales`, `sale_items`,
  `stock_movements`, `user_profiles`
  - ถ้าใช้ระบบเชื่อมต่อ ให้ export `integration_channels`, `channel_listings`, `channel_orders`, `channel_order_lines` ด้วย
  - ไม่ต้อง export `integration_credentials` เพราะถอดไม่ได้ถ้าไม่มีกุญแจ ถ้ากู้ระบบ ให้กรอกคีย์ใหม่
- ไฟล์รูปสินค้าอยู่ใน **Storage → product-images** (โฟลเดอร์ละ 1 แบบสินค้า ตั้งชื่อตามรหัสแบบ) — ตาราง `product_images`
  เก็บแค่ที่อยู่ไฟล์ ถ้าอยากสำรองรูปด้วยให้ดาวน์โหลดจากหน้า Storage
- เก็บไฟล์ไว้ใน Google Drive หรือคอมพิวเตอร์ แยกโฟลเดอร์ตามวันที่

## ข้อห้าม

- **ห้ามลบบิลหรือแก้ตัวเลขสต๊อกตรงๆ ใน Supabase** (ตาราง `sales`, `sale_items`, `stock_movements`,
  ช่อง `products.stock_qty`) — สต๊อกจะไม่ตรงกับประวัติ รายงานเพี้ยน และกู้คืนไม่ได้
- ห้ามลบไฟล์รูปใน Storage `product-images` เอง — ลบรูปจากหน้าแก้ไขสินค้าเท่านั้น (ระบบลบข้อมูลก่อนแล้วค่อยลบไฟล์)
  ถ้าลบไฟล์เองแต่ข้อมูลยังอยู่ หน้าแก้ไขสินค้าจะขึ้น "โหลดรูปไม่ได้" ค้างไว้จนกว่าจะกดลบรูปนั้น
  - ขายผิด/ลูกค้าคืนของ: ใช้ **รับ-จ่ายสต๊อก → รับคืน** เพื่อคืนของเข้าสต๊อก และใส่หมายเหตุเลขที่บิล
    (รายงานยอดขายยังนับบิลเดิม ให้จดยอดคืนเงินแยกไว้)
  - นับของแล้วไม่ตรง: ใช้ **รับ-จ่ายสต๊อก → ปรับยอด** ใส่จำนวนที่นับได้จริง
- ห้ามเปิดเผย `SUPABASE_SERVICE_ROLE_KEY` (ถ้าหลุด ให้กด Reset ที่ Supabase → Project Settings → API แล้วเปลี่ยนใน Vercel + Redeploy)
- ห้ามเปิดเผย `INTEGRATIONS_ENC_KEY`, `INTEGRATIONS_WORKER_SECRET` และคีย์หรือ token ของแพลตฟอร์ม
  - ถ้าคีย์แพลตฟอร์มหลุด ให้ออกคีย์ใหม่ที่แพลตฟอร์ม แล้วกรอกใหม่ในแอป
  - ถ้าค่าลับ worker หลุด ให้สุ่มใหม่ แล้วแก้ทั้งบน Vercel และรัน `supabase-cron-integrations.sql` ใหม่

## เคล็ดลับการสแกนบาร์โค้ด

- **กล้องมือถือ** ต้องเปิดเว็บผ่าน https (เว็บจริงเป็น https อยู่แล้ว) และกดอนุญาตให้ใช้กล้อง
- **เครื่องสแกน USB/Bluetooth** ทำงานเหมือนคีย์บอร์ด ให้ตั้งเครื่องสแกนให้ส่ง Enter ต่อท้าย
  ถ้าคีย์บอร์ดค้างเป็นภาษาไทยอยู่ ระบบจะแปลงรหัสกลับเป็นภาษาอังกฤษให้อัตโนมัติ
- SKU และบาร์โค้ดควรเป็นตัวอักษรอังกฤษ ตัวเลข และสัญลักษณ์เท่านั้น (ภาษาไทยพิมพ์เป็นบาร์โค้ดไม่ได้)
